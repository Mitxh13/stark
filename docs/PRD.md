# PRD — [Project Name]

> Lock this before starting Architecture. Changes after that should be deliberate, not casual.

## Goal
One or two sentences — what are we building and why (pull from research.md).

## Users
Who is this for. Be specific, not "everyone."

## Core features
The must-haves for v1. Bullet list, not prose. Each one should be a real user-facing capability, not a technical detail (technical detail belongs in Architecture).

- Feature 1
- Feature 2
- Feature 3

## Out of scope
For each core feature above, ask: "is there an obvious adjacent thing someone might assume is included?" If yes, name it here. If no, skip it. Aim for 3–5 bullets, not an exhaustive list.

- e.g. "User auth — no social login, no 2FA in v1"
- e.g. "Payments — no refunds flow in v1"

## Success criteria
How do you know this worked? Keep it concrete — a number, a behavior, a "user can do X without help."

## Open questions
Anything still unresolved that Architecture needs to settle.

---

**Exit check:** Could someone else read this and know exactly what to build and what NOT to build, without asking you a follow-up question?
